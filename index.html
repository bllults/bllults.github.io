schema    1,480 tables, 280 PL/SQL packages, 4,200 constraints
question  Container turnover with demurrage penalty risk in Q3?

SELECT c.container_id, c.carrier_code,
       SUM(d.penalty_rate * d.days_overdue) AS total_demurrage
FROM freight_containers c
JOIN demurrage_ledger d ON c.shipment_id = d.shipment_id
WHERE c.status = 'HELD'
  AND d.filing_date BETWEEN DATE '2026-07-01' AND DATE '2026-09-30'
GROUP BY c.container_id, c.carrier_code
HAVING SUM(d.penalty_rate * d.days_overdue) > 5000;

How PureSchema uses Claude

Large schemas are too big for a generic chatbot to handle reliably. PureSchema keeps the whole schema in context and adds its own checks around every answer.

  1. Load the schema

    DDL, PL/SQL packages and constraints go into Claude's context once. Prompt caching keeps follow-up questions fast and cheaper to run.

  2. Plan the query

    Claude breaks the question down and uses tool calls through MCP to inspect the database structure before it writes SQL.

  3. Validate before running

    Each statement is parsed, checked against the schema, filtered through role-based masking and cost-estimated before it reaches your database.

Your data stays with you. Table rows stay in your environment. Claude receives the schema structure and the question, not your records.
